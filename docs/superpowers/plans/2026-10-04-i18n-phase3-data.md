# i18n Phase 3: Language-Specific Test Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the global language is Hungarian, a new run (Smoke, Demo or Full) uses Hungarian test data of the same task types: native Hungarian datasets where they exist, Hungarian versions of the repo's own fixtures, and machine- or human-translated packs elsewhere. English cases stay byte-identical, so frozen English evidence stays valid.

**Architecture:** Each locale gains `prompts.yaml` (repo-authored test text) and `datasets.yaml` (slot → native | translated | generated | missing). Generators (`fresh.py`, `episodes.py`) take a `lang` argument and read templates through `arena/i18n/prompts.py`. English output must stay byte-identical, which is enforced by golden digests captured before the refactor. Native packs are built by one config-driven importer. Translated packs are built from the prepared English packs through a pluggable translation engine and a translation memory. `suite(preset, lang)` assembles a language's packs from `.arena/datasets/<lang>/`. The run manifest records the language, and episodes map localized answers back to stable ids.

**Tech Stack:** Python 3.11, pydantic, PyYAML, huggingface_hub/pyarrow (already used), optional `transformers`+`sentencepiece`+`torch` for the offline Opus-MT engine (optional extra `i18n`), httpx for DeepL/Google; React UI additions through the Phase 1 i18n system.

Spec: `docs/superpowers/specs/2026-10-04-i18n-design.md` section 3 and the data parts of section 4. Phase 1 is complete (locales, `arena/i18n/`, UI).

- **Do not modify** `arena/importers.py`, `arena/multilingual.py`, `arena/abcd.py`, `arena/wire.py`, `arena/contracts.py`, `arena/scoring.py`. The English import path and the frozen ABCD assessment (whose runner fingerprints `arena/abcd.py`) stay untouched. New code lives in new modules.
- **Binary (`noul`) questions keep labels `["no","yes"]`** in every language, because `wire.py` and the workers treat them as protocol ids. Only the question text is localized. Score questions keep labels `"0".."4"`. Choice labels are localized.
- **Every localized case** carries `language=<code>` and an id prefixed `<code>:`. Every localized choice case carries `provenance["label_ids"] = {localized_label: stable_id}`, where stable ids are the English labels.
- **Non-English packs** live in `.arena/datasets/<lang>/`. English paths do not change. Third-party and translated text is never committed.
- **No English fallback in test data.** If `prompts.yaml` lacks a key for a language, generation raises an error. (The UI falls back to English; test data must not mix languages silently.)
- **Run language.** It is the global setting at run start, recorded in `manifest["language"]`. Runs without the field are `en`. `RunRequest` is unchanged.
- **ABCD.** It is a separate frozen assessment with its own runner. In `hu/datasets.yaml` it is `source: missing` with reason `"separate frozen assessment; Hungarian ABCD is a follow-up"`.
- **Python** is always run as `uv run --frozen`. The one exception is Task 2, which refreshes `uv.lock` deliberately.
- **Hungarian test text** must be natural, use the informal "te" form, and follow `docs/i18n/glossary-hu.md`. Every factual or policy sentence must keep the exact logic of the English one, since the gold answers derive from it.

**Files:**

**Interfaces:**
- `datasets.py`, pydantic models:

```python
class LabelEntry(BaseModel): id: str; label: str
class Slot(BaseModel):
    source: Literal["native", "translated", "generated", "missing"]
    pack: str; family: str
    reason: str | None = None                     # required when missing
    repo: str | None = None; revision: str | None = None; config: str | None = None
    files: list[str] = []                          # repo-relative parquet/jsonl paths (native)
    fields: dict[str, str] = {}                    # text/premise/hypothesis/label → column
    sample: int | None = None; seed: int = 5090
    drop_labels: list[str] = []
    label_group: str | None = None                 # prompts.yaml labels.<group>
    source_label_ids: dict[str, str] = {}          # raw dataset label value → stable id
    question: str | None = None                    # prompts.yaml key
    state: str | None = None                       # prompts.yaml key for multi-field state
    licence: str = ""
    engine: str | None = None                      # translated default engine
class LanguageDatasets(BaseModel): slots: dict[str, Slot]
def load_slots(lang: str) -> dict[str, Slot]
def expected_counts(lang: str) -> dict[str, int]   # pack name → expected cases (generated slots computed from generators)
```

- `en/datasets.yaml` describes today's English sources. All of them are `native`, except `fresh`/`robustness`/`episodes`, which are `generated`. English packs keep being built by the existing importers. `en` `datasets.yaml` is descriptive and supplies the expected counts.
- `native.build(lang, slot_id, slot) -> list[Case]`:
  - **Download:** fetch the pinned files with `hf_hub_download(repo, file, repo_type="dataset", revision=…, local_dir=DATASETS/lang/"raw"/…)`.
  - **Sampling:** read rows, drop `drop_labels`, then take a stratified sample using the same algorithm as `importers.stratified` (re-implement it in `packs.py`, since `importers.py` must not change).
  - **Case construction:** map labels through `source_label_ids` to ids, then through `labels(lang, label_group)` to localized labels. Build state from `fields`/`state` and the question from the `question` key. Ids are `f"{lang}:{slot_id}-{row_key}"`. Set `language` and `label_status="public"`. Provenance records repo, revision, file sha256, licence and `label_ids`.
- `packs.save(lang, pack_file, cases, expected)` writes `.arena/datasets/<lang>/<pack_file>-cases.jsonl` plus a manifest. It mirrors `importers.save`, with `"language": lang` and the slot licences.
- `packs.prepare_language(lang, progress)` builds every native and generated slot of the language. Generated slots need no files. Translated slots are added in Task 6. One file per English pack name: `classification`, `multilingual`, `rag`, `typed`, `jevbench`.
- **Pins.** The implementer resolves and pins the current dataset revisions at implementation time with `HfApi().dataset_info(repo).sha`, and writes the exact files used. Check the licences on the dataset cards and record them, for example "CC-BY-SA-4.0 (HuSST GitHub; HF card says BSD-2-Clause — treated as share-alike)".

### Task 6: Translation engines, translation memory and translated packs

**Files:**
- Create: `arena/i18n/engines.py`, `arena/i18n/memory.py`, `arena/i18n/translated.py`, `tests/test_i18n_translate.py`
- Modify: `arena/i18n/__main__.py` (`translate`, `review`, `tm export|import`, `prepare`), `arena/i18n/packs.py` (translated slots), `locales/hu/prompts.yaml` (`labels.banking77`), `.env.example` (DEEPL_API_KEY, GOOGLE_TRANSLATE_API_KEY, commented)

**Interfaces:**

```python
class Engine(Protocol):
    name: str; model: str; revision: str
    def translate(self, texts: list[str], src: str, tgt: str) -> list[str]: ...
ENGINES: dict[str, Callable[[], Engine]]  # "manual", "opus-mt", "deepl", "google", "fake"
```

- **`fake`** (for tests only, not listed in help) returns `f"[{tgt}] {text}"`.
- **`opus-mt`** loads `Helsinki-NLP/opus-mt-{src}-{tgt}` at a pinned revision through `transformers` (the optional extra). Missing dependencies raise a clear error naming `uv sync --extra i18n`. It batches 16 texts at a time with `max_length=512`. Texts longer than about 400 tokens are split on sentence boundaries and rejoined.
- **`deepl`/`google`** call the official REST APIs with `httpx` (DeepL Free `https://api-free.deepl.com/v2/translate`; Google `https://translation.googleapis.com/language/translate/v2`). Keys are read from the environment and never logged. Missing keys raise a clear error.
- **`manual`** writes the pending texts to `.arena/translations/<lang>/<slot>.pending.jsonl` (`{src_sha256, src}`) and raises `ManualPending(path)`. `tm import` reads a file of `{src_sha256, tgt}` rows back in.
- `memory.TranslationMemory(lang, slot)` is backed by `.arena/translations/<lang>/<slot>.jsonl` (one row per source: `{src_sha256, src, tgt, engine, model, revision, at, reviewed}`):
  - `get(src) -> str | None`
  - `put_many(rows)`
  - `missing(texts) -> list[str]` (deduplicated)
  - `sha256() -> str` (of the file)
  - `export(path)` / `import_(path)`, which keeps `reviewed`
- `translated.texts_for(slot_id, english_cases) -> list[str]` lists the unique source texts needed: states, question texts, criteria descriptions, and SciFact claims, titles and documents. Labels are never translated here; they come from `prompts.yaml` labels groups. For translated slots that have native label sets (typed-decisions, JevBench), the label sets are translated once through the TM, and uniqueness is checked.
- `translated.build(lang, slot_id, slot, english_cases, tm) -> list[Case]` produces the localized copy of each English case:
  - **Ids:** id `f"{lang}:{id}"` and the same cluster prefix.
  - **Language:** `language=lang`.
  - **Text:** state and question text come from the TM.
  - **Labels:** choice labels are mapped through the label group or the translated label map. `noul`/`score` labels are kept. `criteria` dict keys are remapped to localized labels and the values translated.
  - **Gold:** `gold`, `acceptable` and `reference_probs` keys are remapped.
  - **Provenance:** `provenance` gets `translated_from`, `engine`, `tm_sha256`, `label_ids`, and `reviewed_fraction`.
  - **Missing translations:** if any text is missing from the TM, raise `MissingTranslations(n)`.
- `prepare_language(lang)`:
  - **Translated slots:** these need the English packs prepared first. Read them from `.arena/datasets/*-cases.jsonl` filtered by pack/family. Then run `translate` for missing texts with the slot's engine and build.
  - **Missing English prerequisite:** report `"prepare English datasets first"` and continue with the other slots.
- **CLI:**
  - `translate --lang L --slot S [--engine E] [--dry-run]`: the dry run prints the unique text count, total characters, and the DeepL/Google free-tier note (500,000 characters per month).
  - `review --lang L --slot S [--sample N] [--seed]`: prints source and translation side by side and asks y/n/e(dit)/q for each one. It writes `reviewed: true` or an edited target, and uses `input()` so it can be tested with monkeypatch.
  - `tm export|import --lang L --slot S FILE`.
  - `prepare --lang L [--only native|translated|generated]`.

**Hungarian content:** `labels.banking77` holds Hungarian labels for the 77 BANKING77 intents. The ids are the English intent names, and the Hungarian labels must be unique and readable (lowercase, underscores).
